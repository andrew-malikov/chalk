# Electrobun for Review Desktop

Research date: 2026-10-04. Official documentation inspected at the v2.0.2 tag; no application benchmark or compatibility prototype was run.

## Recommendation

Keep Electron while Review Desktop retains the Code OSS workbench. Electrobun is a reasonable candidate for a future React-owned shell after retiring those workbench dependencies. Bundled CEF supplies Chromium rendering; the cited Electrobun documentation does not establish compatibility with Electron's APIs or the Code OSS desktop host.

The current migration already moves the primary Diff tab and commit comparisons to React `@pierre/diffs`, explicitly to support later shell replacement. Document peeks still use Monaco, and source editing and language services remain in Code OSS. See [the migration record](../plans/2026-10-04-pierre-diffs-port.md), [ReviewCanvasBridge](../../packages/review-protocol/src/contracts.ts), and [the workbench integration](../../apps/review-desktop/code-oss/src/vs/review).

## Verified framework facts

| Concern | Official behavior | Implication here |
| --- | --- | --- |
| Current release | GitHub's latest stable release is v2.0.2, published 2026-09-29. [Release](https://github.com/blackboardsh/electrobun/releases/tag/v2.0.2) | Advice describing Bun as the current default is outdated. |
| Main process | Cottontail, a JavaScriptCore-based runtime targeting Node.js and Bun API compatibility, is the default. Actual Bun is an explicit alternative. Hutch owns build orchestration. [Architecture](https://github.com/blackboardsh/electrobun/blob/v2.0.2/docs/src/content/docs/electrobun/guides/architecture/overview.mdx), [runtime](https://github.com/blackboardsh/electrobun/blob/v2.0.2/docs/src/content/docs/electrobun/guides/cottontail.mdx) | Retaining an existing Node server requires compatibility testing or packaging Node separately. |
| Browser engine | Defaults: WKWebView on macOS, WebView2 on Windows, WebKitGTK 4.1 on Linux. Optional bundled CEF pins Chromium and materially increases download and installed size. macOS/Windows can mix renderers; Linux selects one implementation per process. [CEF guide](https://github.com/blackboardsh/electrobun/blob/v2.0.2/docs/src/content/docs/electrobun/apis/bundling-cef.mdx) | Avoiding bundled Chromium is the main potential size benefit. Test the same canvas in system webviews before assuming browser compatibility. |
| IPC and isolation | The main process owns privileged native APIs. Webviews use typed RPC over encrypted loopback transport with native-bridge fallback. The browser engine controls its OS process model. [Architecture](https://github.com/blackboardsh/electrobun/blob/v2.0.2/docs/src/content/docs/electrobun/guides/architecture/overview.mdx), [RPC](https://github.com/blackboardsh/electrobun/blob/v2.0.2/docs/src/content/docs/electrobun/apis/browser/electroview-class.mdx) | Existing host protocols need adapters. TypeScript schemas do not by themselves demonstrate runtime validation of untrusted input. |
| Embedded views | Multiple BrowserViews can have explicit bounds. `<electrobun-webview>` synchronizes a native child view with host layout. Its native layer sits above host DOM, so overlays need masks. Windows mask/passthrough behavior requires CEF. `sandbox` disables Electrobun RPC while preserving events/navigation. [BrowserView](https://github.com/blackboardsh/electrobun/blob/v2.0.2/docs/src/content/docs/electrobun/apis/browser-view.mdx), [webview tag](https://github.com/blackboardsh/electrobun/blob/v2.0.2/docs/src/content/docs/electrobun/apis/browser/electrobun-webview-tag.mdx) | Multi-view layout is supported, with compositing constraints that matter for document peeks and floating canvas controls. |
| Distribution | Hutch packages releases and supports macOS signing/notarization. Updates use static HTTPS hosting, optional delta patches, full-download fallback, and a post-exit replacement helper. Bundle hashes are routing identifiers; authentication relies on HTTPS and platform signing. [Signing](https://github.com/blackboardsh/electrobun/blob/v2.0.2/docs/src/content/docs/electrobun/guides/code-signing.mdx), [updates](https://github.com/blackboardsh/electrobun/blob/v2.0.2/docs/src/content/docs/electrobun/guides/updates.mdx) | A replacement shell still needs a release pipeline and update migration. |
| Platforms and maintenance | v2.0.2 lists macOS 14+, Windows 11+, Ubuntu 24.04+ as official. Compatibility docs list macOS arm64, Windows x64, Linux x64/arm64. The README says there is no expectation that maintainers will review, respond to, or merge issues/PRs. [README](https://github.com/blackboardsh/electrobun/blob/v2.0.2/README.md), [compatibility](https://github.com/blackboardsh/electrobun/blob/v2.0.2/docs/src/content/docs/electrobun/guides/compatability.mdx) | Check supported targets and maintenance expectations against Review's release requirements. |

## Remaining evidence needed

Review's local server uses `node:sqlite` `DatabaseSync` and `backup` in [store.ts](../../packages/review/src/review-api/store.ts) and related modules. Electrobun's compatibility docs caution that native addons and runtime internals can differ. Exact support for these SQLite paths was not established in this investigation. Using a Node sidecar is an option to investigate, not a verified implementation.

Before a shell decision, run the same React UI and server workload in Electron and Electrobun. Measure cold start, installed size, memory, and canvas interaction latency. Exercise peeks, filesystem access, shortcuts and menus, language services, and packaged update behavior on each intended OS. No measured savings for this application are available yet.
