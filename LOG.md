# Deferred work

## Pierre diff port

These scope reductions are implemented in the first port. The Diff tab and commit comparisons use Pierre; native peeks and source editors still use Code OSS. See [the port plan](docs/plans/2026-10-04-pierre-diffs-port.md).

| Deferred capability                                                             | First-port behavior                                                                                                                                              | Restore when                                                                                                                              |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Structural line correspondence and syntax-span change highlights                | Diff tab and commit comparisons show conventional Git text diffs with Shiki syntax highlighting.                                                                 | A separate probe proves an affordable mapping of diffr correspondence and spans onto Pierre's supported APIs.                             |
| Provider-authored folds, generated-code hiding, and asynchronous fold summaries | New viewer uses ordinary unchanged-context expansion and file collapse; textual progress includes textual changes.                                               | Region identity, asymmetric folds, labels, and reader overrides can be supported without maintaining a custom renderer.                   |
| Exact lens range masking and syntax-scope context                               | Basic lenses select matching files and reveal source ranges; full file diffs remain visible. Viewed actions remain scoped to authored ranges.                    | Range projection can preserve source numbering, two-sided context, and navigation without synthetic source files.                         |
| Document code peeks on Pierre                                                   | Existing native peeks retain search, sizing, pinned sources, and language interactions; comparisons and viewed overlays use textual mode with the canvas.        | Primary diff surfaces are stable, then peeks migrate through the same data/renderer path with document-find and height behavior verified. |
| Inline language-service hover and definition navigation inside Pierre diffs     | Readers open the pinned source range in the existing source editor. Source-editor language services remain available.                                            | A measured product need justifies a renderer-independent language-feature bridge.                                                         |
| Reuse of old Monaco diff scroll state                                           | Pierre gets a new anchor-based view-state namespace; native peeks retain their own state.                                                                        | A concrete need for one-time state migration outweighs the widget-format coupling.                                                        |
| Complete removal of Code OSS                                                    | Desktop shell, source editor, native peeks, and their services stay in place.                                                                                    | These remaining responsibilities have their own scoped replacement plans.                                                                 |
| Full-source context expansion in live worktree diffs                            | Live patches refresh with worktree changes; committed comparisons support context expansion, but live patches do not hydrate from independently read file bytes. | An atomic patch/source transport or verified generation boundary prevents mixing different worktree contents.                             |
| Rendering patches above 500,000 bytes per file                                  | Show an explicit oversized-patch notice and source-opening access. Request the existing 500,000-byte maximum for smaller files.                                  | Measurements justify raising the transport limit or a supported chunked rendering path.                                                   |

Record additional regressions only when implementation demonstrates them, with the affected behavior and a checkable restoration condition.
